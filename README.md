# AI Phone Assistant (Android + Cloud API)

Стартовый проект для realme / Android 16: Kotlin + Jetpack Compose и отдельный Node.js API-шлюз.
Функции каркаса: маршрутизация запросов к OpenAI, Gemini и Claude; погода Open-Meteo;
вызов действий Home Assistant; голосовой ввод/озвучивание на Android.

## Важно
Это исходный MVP-каркас, а не готовый APK. Его нужно открыть в Android Studio, проверить сборку
на конкретной прошивке realme и настроить сервер/ключи. Фоновое распознавание ключевой фразы
«Ассистент» пока оставлено отдельным модулем WakeWordEngine: для настоящего always-on wake word
нужен движок (например, Porcupine) и его лицензионный AccessKey. Не используем непрерывный
SpeechRecognizer как подмену wake-word движка.

Android 14+ ограничивает запуск микрофонного foreground service из фона. Первый запуск службы
должен происходить при видимой Activity после выдачи RECORD_AUDIO. Перезапуск после reboot
не может самовольно поднимать microphone FGS.

## Состав
- `android/` — приложение Kotlin.
- `server/` — API-шлюз. API-ключи хранятся только на сервере.
- Home Assistant — универсальный мост для устройств разных брендов.
- Музыка — управление доступными Android media sessions; управление сторонними сервисами
  зависит от их приложения, активной media session и выданного Notification access.

## Запуск сервера
1. Установить Node.js 20+.
2. `cd server && npm install`
3. Скопировать `.env.example` в `.env` и заполнить ключи.
4. `npm start`

## Запуск Android
1. Открыть папку `android/` в Android Studio (JDK 17, Android SDK 36).
2. Указать `API_BASE_URL` в `android/app/build.gradle.kts` или заменить локальный адрес сервера.
3. Собрать и установить приложение.
4. Открыть приложение, выдать разрешение микрофона и запустить голосовую службу кнопкой.

## API
`POST /v1/assistant` JSON: `{ "text": "...", "provider": "auto|openai|gemini|claude" }`
`GET /v1/weather?lat=50.45&lon=30.52`
`POST /v1/home/action` JSON: `{ "entity_id":"light.kitchen", "service":"turn_on", "domain":"light" }`

Для Home Assistant задайте `HA_BASE_URL` и `HA_TOKEN`. Разрешайте только известные домены
и entity_id. В production добавьте пользовательскую авторизацию, HTTPS, rate limit и аудит.


## Яндекс Музыка
Добавлен `MusicController.kt`:
- открывает официальное приложение `ru.yandex.music` (или сайт как fallback);
- отправляет play/pause/next/previous через Android MediaSession;
- позволяет открыть URL трека/альбома/плейлиста с домена music.yandex.ru;
- добавлены элементы управления в экран приложения.

Для управления активным медиасеансом открой в приложении «Разрешить управление музыкой»
и включи доступ к уведомлениям для AI Phone Assistant в системных настройках Android.
Затем запусти Яндекс Музыку и начни воспроизведение хотя бы один раз. Управление работает
только пока приложение Яндекс Музыки предоставляет активный MediaSession. Поиск по каталогу,
чтение личной медиатеки и запуск произвольного плейлиста по названию не реализованы через
официальный публичный API в этом MVP; для конкретного плейлиста можно передать URL Яндекс Музыки.


## Обновлённый интерфейс и управление экраном
В Android-приложение добавлен тёмный интерфейс на Material 3 и базовый мост через
`AccessibilityService` (`ScreenControlService.kt`):
- чтение доступного текстового содержимого активного окна по запросу;
- поиск элемента по тексту и нажатие после отдельного подтверждения;
- ввод текста в уже сфокусированное поле;
- прокрутка вперёд и системная команда «Назад».

### Как включить управление экраном
1. Установить APK и открыть AI Phone Assistant.
2. В разделе «Управление экраном» нажать «Открыть настройки доступности».
3. Найти AI Phone Assistant и вручную включить службу. Android покажет предупреждение
   о широких возможностях службы доступности — внимательно прочитай его.
4. Вернуться в приложение. Нажать «Прочитать текущий экран» или выполнить одно из
   доступных действий. Для нажатия по тексту приложение отдельно спросит подтверждение.
5. Чтобы отключить функцию, выключить службу в тех же системных настройках Android.

Ограничения: читается только то, что приложение может предоставить через дерево
доступности. Защищённые окна, часть игр, видео, банковские экраны и графические элементы
без accessibility-описаний могут быть недоступны. Сервис не снимает блокировку, не
обходит защиту приложений и не должен использоваться для ввода паролей, платежей или
подтверждения критичных операций. В текущем MVP команды экрану запускаются из интерфейса
приложения; самостоятельный AI-агент, который планирует и выполняет цепочки действий,
ещё не подключён. Не оставляй службу включённой, если не пользуешься ею.

## Сборка тестового APK через GitHub Actions
В этой рабочей среде нет Android SDK, Gradle и Android build-tools, поэтому APK здесь
не был собран и не должен считаться проверенным. В проект добавлен workflow
`.github/workflows/build-apk.yml`:
1. Загрузите проект в свой GitHub-репозиторий.
2. Откройте вкладку Actions и запустите `Build debug APK` (или отправьте push в main/master).
3. После успешной сборки скачайте artifact `AIPhoneAssistant-debug`.
4. Внутри будет `app-debug.apk`.

Это debug APK для тестирования, не подписанный релиз. Для установки разрешите установку
приложений из выбранного источника на телефоне. Перед реальным использованием настройте
HTTPS API-сервер и проверьте разрешения Android.


## AI Council — совместная работа моделей

Endpoint `POST /v1/council` выполняет независимый анализ всеми настроенными провайдерами (нужно минимум два ключа), передаёт полученные анализы обратно моделям для перекрёстной проверки и просит координатора собрать единый ответ. Ответ содержит `participants`, `analyses`, `reviews` и итоговый `answer`. В Android-интерфейсе для этого есть кнопка «Запустить совет трёх ИИ». Запросы оплачиваются отдельно у каждого провайдера: при трёх ключах обычно выполняется до семи обращений к моделям на одну задачу.

Совместная работа не означает прямое соединение моделей между собой: обмен организует серверный координатор. Не отправляйте пароли, платёжные данные или другие секреты в общий контекст. Результаты моделей являются рекомендациями; управление телефоном и важные действия требуют отдельной проверки и подтверждения.


## Два режима ИИ

В приложении доступны оба режима:

- **Один ИИ** — выбор Авто, ChatGPT, Gemini или Claude. В режиме Авто сервер использует первый доступный провайдер в заданном порядке; это не параллельный запуск моделей.
- **Объединение ИИ (AI Council)** — минимум две подключённые модели независимо анализируют запрос, получают результаты коллег для перекрёстной проверки, после чего координатор формирует единый ответ. Для участия всех трёх моделей нужны все три API-ключа.

Переключение режима не удаляет и не меняет API-ключи. Все ключи хранятся только на сервере в переменных окружения.
